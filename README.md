# Програмний проєкт 3 - варіант 8

Виконання обчислення за схемою №8 у `nt = 4` потоках (крім `main`).
Набори дій: a=5, b=6, c=4, d=8, e=9, f=6, g=6, h=9, i=7, j=6, k=4 (усього 70 дій).
Кожна дія `f(x, i)` триває 1 с, тож мінімальний час - 18 с (⌈70 / 4⌉), і програма його досягає.

## Вимоги

- компілятор з підтримкою C++20 (перевірено на g++ 15.2.0, MSYS2 UCRT64);
- CMake 3.20+.

## Збирання

З папки проєкту:

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
```

Без CMake:

```powershell
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic src/main.cpp -o prog.exe
```

## Запуск

```powershell
build\prog.exe
```

Записати вивід у файл:

```powershell
build\prog.exe > results.txt
```

## Що виводить програма

```text
Обчислення розпочато.
З набору a виконано дію 1.
...
З набору f виконано дію 6.
Обчислення завершено. Тривалість обчислення 18.147 секунд.
```

Кожна з 70 дій друкується рівно один раз. Порядок рядків у межах однієї секунди
може відрізнятися між запусками, бо чотири потоки завершують дії майже одночасно.

## Як це працює

- Кожен вузол схеми - це `std::latch`, лічильник якого дорівнює кількості дій на вхідних дугах
  (`done_a`=5, `done_b`=6, `done_cg`=10, `done_ed`=17, `done_j`=6, `done_hi`=16).
- Перед блоком дій набору потік викликає `wait()` на latch початкового вузла дуги,
  після кожної дії - `count_down()` на latch кінцевого вузла.
- Розподіл дій по потоках зафіксовано в таблицях `plan_t1`…`plan_t4`;
  `static_assert` під час компіляції перевіряє, що кожна дія призначена рівно один раз.

| Потік | Послідовність | Дій |
| --- | --- | --- |
| T1 | a1-a2, c1-c4, j1-j6, f1-f6 | 18 |
| T2 | a3-a4, e1-e2, g1-g2, e4-e8, i1-i4, h9, k1-k2 | 18 |
| T3 | a5, b5-b6, e3, g3-g4, d1-d4, e9, i5-i7, h7-h8, k3 | 17 |
| T4 | b1-b4, g5-g6, d5-d8, h1-h6, k4 | 17 |
